### 数据流转

- **wiki 文件**：`/root/kgqa/data/wiki/`（source of truth；entities/topics/sources/queries/synthesis/comparisons/_growth）
- **配置加密**：`/root/kgqa/data/cache/.fernet.key` + `system_config.json`（Fernet 加密的 LLM/Embedding API key）
- **公告图片等上传**：`/root/kgqa/data/uploads/announcements/`
- **MySQL 业务数据**：docker named volume `kgqa_mysql_data`
- **图谱缓存**：`/root/kgqa/data/wiki/graph-data.json`（builder 写盘，前端从 backend 读）

### 域名与证书

- DNS：kb.example.com / www.kb.example.com → A 记录 `YOUR_SERVER_IP`
- nginx server_name 锁定 kb.example.com / www.kb.example.com，IP 直访被拒
- 80 端口仅保留 `/.well-known/acme-challenge/`（certbot renew）+ 全部 301 到 https
- backend `CORS_ORIGINS = "http://kb.example.com,https://kb.example.com,http://YOUR_SERVER_IP,http://localhost"`

## 2. SSH 自动化模板（Claude 用）

> 给 Claude 一份能直接跑的 paramiko 框架。所有云端改动都按这个模板：上传文件 → docker cp 到容器 → restart。

```python
import sys, paramiko
sys.stdout.reconfigure(encoding='utf-8', errors='replace')

c = paramiko.SSHClient()
c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
c.connect("YOUR_SERVER_IP", username="root", password="CHANGE_ME",
          timeout=20, look_for_keys=False, allow_agent=False)

def run(cmd, timeout=120, expect_zero=True):
    print(f"\n$ {cmd}"); sys.stdout.flush()
    _, o, e = c.exec_command(cmd, timeout=timeout)
    out = o.read().decode("utf-8","replace").strip()
    err = e.read().decode("utf-8","replace").strip()
    rc = o.channel.recv_exit_status()
    if out: print(out[-3000:])
    if err: print("[stderr]", err[-1500:])
    print(f"[rc={rc}]")
    if expect_zero and rc != 0:
        c.close(); sys.exit(1)
    return out, err, rc

# 上传文件:
sftp = c.open_sftp()
sftp.put("D:/local/path", "/root/kgqa/remote/path")
sftp.close()

# ...run 命令...
c.close()
```

⚠️ Windows 终端默认 GBK，打印中文会爆 `UnicodeEncodeError`。脚本顶部务必加 `sys.stdout.reconfigure(encoding='utf-8')`。

## 3. 增量改代码（最常用）

> 不重新 build 镜像，把改动的文件 `docker cp` 进现有容器即可。秒级生效。

### 3.1 改后端单个 .py 文件

```python
# 上传 + 灌进容器 + 重启 backend
sftp.put("D:/kg-qa-ie/backend/app/api/v1/xxx.py", "/root/kgqa/_patch/xxx.py")
run("docker cp /root/kgqa/_patch/xxx.py kgqa-backend-1:/app/app/api/v1/xxx.py")
run("docker compose -f /root/kgqa/docker-compose.yml restart backend")
import time; time.sleep(8)
run("docker logs kgqa-backend-1 --tail 20")
```

### 3.2 改前端

前端是静态资源，**本地 build 后** scp 整个 `dist` 进 frontend 容器的 nginx 静态目录：

```bash
# 本地
cd D:/kg-qa-ie/frontend && npm run build
cd D:/kg-qa-ie/frontend && tar czf /d/kg-qa-ie/_release/frontend_dist.tar.gz dist
```

```python
# 远程
sftp.put("D:/kg-qa-ie/_release/frontend_dist.tar.gz", "/root/kgqa/frontend_dist.tar.gz")
run("cd /tmp && rm -rf dist && tar xzf /root/kgqa/frontend_dist.tar.gz")
run("docker exec kgqa-frontend-1 sh -c 'rm -rf /usr/share/nginx/html/*'")
run("docker cp /tmp/dist/. kgqa-frontend-1:/usr/share/nginx/html/")
run("docker exec kgqa-frontend-1 nginx -s reload || true")
```

### 3.3 改后端环境变量 / nginx 配置

修改 `/root/kgqa/docker-compose.yml` 或 `/root/kgqa/nginx/default.conf` 后：

```python
# CORS / DATABASE_URL 之类 env 改了 → 重启 backend
run("cd /root/kgqa && docker compose up -d --force-recreate backend")

# nginx 配置改了 → reload(不停服)
run("docker exec kgqa-nginx-1 nginx -t")  # 先校验语法
run("docker exec kgqa-nginx-1 nginx -s reload")
```

## 4. 数据迁移（本地 ↔ 服务器）

### 4.1 本地导出（先备份）

```bash
# wiki/ + cache/(含 fernet key + system_config) + uploads/
cd D:/kg-qa-ie/backend/data && tar czf /d/kg-qa-ie/_release/wiki_data.tar.gz wiki
cd D:/kg-qa-ie/backend/data && tar czf /d/kg-qa-ie/_release/cache_data.tar.gz cache
cd D:/kg-qa-ie/backend/data && tar czf /d/kg-qa-ie/_release/uploads_data.tar.gz uploads

# MySQL(本地容器叫 deploy-mysql-1)
docker exec deploy-mysql-1 sh -c "mysqldump --single-transaction -uroot -pCHANGE_ME kg_qa_ie 2>/dev/null" > D:/kg-qa-ie/_release/mysql_dump.sql
```

### 4.2 推到云服务器（覆盖式）

⚠️ **会清空 MySQL 当前内容**。仅在"本地权威 → 服务器"模式用。

```python
sftp.put("D:/kg-qa-ie/_release/mysql_dump.sql", "/root/kgqa/mysql_dump.sql")
sftp.put("D:/kg-qa-ie/_release/wiki_data.tar.gz", "/root/kgqa/wiki_data.tar.gz")
sftp.put("D:/kg-qa-ie/_release/cache_data.tar.gz", "/root/kgqa/cache_data.tar.gz")

# wiki:解压前先 backup 现网
run("cd /root/kgqa && tar czf data/wiki.bak.$(date +%s).tar.gz data/wiki")
run("rm -rf /root/kgqa/data/wiki && cd /root/kgqa/data && tar xzf /root/kgqa/wiki_data.tar.gz")

# cache:同上
run("cp -r /root/kgqa/data/cache /root/kgqa/data/cache.bak.$(date +%s)")
run("rm -rf /root/kgqa/data/cache && cd /root/kgqa/data && tar xzf /root/kgqa/cache_data.tar.gz")

# MySQL:drop + restore
run("docker exec -i kgqa-mysql-1 mysql -uroot -pCHANGE_ME -e 'DROP DATABASE IF EXISTS kg_qa_ie; CREATE DATABASE kg_qa_ie CHARACTER SET utf8mb4;' 2>&1 | grep -v Warning")
run("docker exec -i kgqa-mysql-1 mysql -uroot -pCHANGE_ME kg_qa_ie < /root/kgqa/mysql_dump.sql 2>&1 | grep -v Warning")

# 重启 backend
run("cd /root/kgqa && docker compose restart backend")
```

### 4.3 云服务器导出回本地（备份）

```python
run("docker exec kgqa-mysql-1 sh -c 'mysqldump --single-transaction -uroot -pCHANGE_ME kg_qa_ie 2>/dev/null' > /root/kgqa/_export/mysql_dump.sql")
run("cd /root/kgqa/data && tar czf /root/kgqa/_export/wiki.tar.gz wiki")

# scp 拉回本地
sftp.get("/root/kgqa/_export/mysql_dump.sql", "D:/kg-qa-ie/_release/mysql_dump.sql")
sftp.get("/root/kgqa/_export/wiki.tar.gz", "D:/kg-qa-ie/_release/wiki.tar.gz")
```

### 4.4 注意事项

- **fernet key 必须保留**：丢了 = 所有 LLM API key 解不开 = 必须重新填配置
- **不要双向同时写**：服务器和本地同时改 wiki/MySQL 后合并极易出冲突。选一边作为权威。
- **wiki 文件改了不会触发图谱重建**：手动调一次 `POST /api/v1/graph/rebuild`（admin token）

## 5. 重新构建与发布镜像（大改后）

> 只在改了依赖（pyproject.toml / package.json）或 Dockerfile 时才需要。一般小代码改用第 3 节的 `docker cp`。

### 5.1 本地 build

```bash
cd D:/kg-qa-ie
docker build -t kgqa-backend:latest -f backend/Dockerfile backend
docker build -t kgqa-frontend:latest -f frontend/Dockerfile frontend
docker save -o D:/kg-qa-ie/_release/kgqa-images.tar \
  kgqa-backend:latest kgqa-frontend:latest \
  mysql:8.0 neo4j:5.24 chromadb/chroma:0.5.15 nginx:1.27-alpine
gzip -1 D:/kg-qa-ie/_release/kgqa-images.tar
```

⚠️ 注意：本地 Docker Desktop 配了 registry-mirror + proxy。如果这次 mirror 挂了/proxy 不通，base 镜像会拉失败。两条出路：
- 本地确保走梯子，docker pull 通了再 build
- 或者：现成的 base 还在 buildkit cache 里，给 build 加 `--cache-from` 或者复用之前已构建的镜像 `docker commit` 现有容器

### 5.2 推到云服务器

```python
# 上传(~1GB,大概 12 分钟@1.4MB/s)
sftp.put("D:/kg-qa-ie/_release/kgqa-images.tar.gz", "/root/kgqa/kgqa-images.tar.gz")
# 加载
run("cd /root/kgqa && gunzip -c kgqa-images.tar.gz | docker load", timeout=600)
# 重新拉起
run("cd /root/kgqa && docker compose up -d")
# 清理
run("rm /root/kgqa/kgqa-images.tar.gz")
```

## 6. HTTPS 证书续签

证书到期前两周（2026-08 月初前）跑一次 renew：

```python
run(
    "certbot renew "
    "--config-dir /root/kgqa/certbot/conf "
    "--work-dir /tmp/certbot-work "
    "--logs-dir /tmp/certbot-log "
    "--webroot --webroot-path=/root/kgqa/certbot/www"
)
run("docker exec kgqa-nginx-1 nginx -s reload")
```

要做成自动续签的话，加一个 cron：

```bash
# /etc/cron.d/certbot-renew
0 4 * * * root certbot renew --quiet --config-dir /root/kgqa/certbot/conf --work-dir /tmp/certbot-work --logs-dir /tmp/certbot-log --webroot --webroot-path=/root/kgqa/certbot/www && docker exec kgqa-nginx-1 nginx -s reload
```

### 7.2 后端 API 返回 500

让 backend 自己跑 router 代码，绕过鉴权与网络层，直击异常：

```python
run('''docker exec kgqa-backend-1 python -c "
import asyncio
from app.core.config import settings
# ... import 你的 service ...
async def m():
    try:
        # 调你怀疑的代码
        ...
        print('OK')
    except Exception:
        import traceback; traceback.print_exc()
asyncio.run(m())
"''')
```

### 7.3 MySQL 直接查

```python
# 中文显示乱:用 hex() 看真实字节
run("docker exec kgqa-mysql-1 mysql -uroot -pCHANGE_ME -Nse 'select id, hex(username), email from kg_qa_ie.users' 2>&1 | grep -v Warning")

# 进 mysql shell
run("docker exec -it kgqa-mysql-1 mysql -uroot -pCHANGE_ME kg_qa_ie")
```

### 7.4 alembic 迁移

backend 启动时自动 `alembic upgrade head`。手动跑：

```python
run("docker exec kgqa-backend-1 alembic current")
run("docker exec kgqa-backend-1 alembic upgrade head")
```

### 7.5 知识图谱 500（出现过的真实问题）

**症状**：`/api/v1/graph/data` 返 500 + pydantic ValidationError。

**根因**：某 wiki 页 frontmatter 里 tags / domains 写成嵌套 list，graph-data.json 里跟着脏。

**定位**：

```python
run('''docker exec kgqa-backend-1 python -c "
import asyncio
from app.core.config import settings
from app.services.graph.builder import load_graph_data_json
async def m():
    p = await load_graph_data_json(wiki_root=settings.wiki_root_path)
    for i,n in enumerate(p.get('nodes',[])):
        for k in ('tags','domains'):
            for j,x in enumerate(n.get(k) or []):
                if not isinstance(x, str):
                    print(i, n.get('id'), k, j, type(x).__name__, repr(x)[:80])
asyncio.run(m())
"''')
```

**修复**：触发一次图谱重建（builder 已带 `_flatten_strs`）：

```python
run('''docker exec kgqa-backend-1 python -c "
import asyncio
from app.core.config import settings
from app.services.graph.builder import build_graph_data, write_graph_data_json
async def m():
    p = await build_graph_data(wiki_root=settings.wiki_root_path)
    await write_graph_data_json(wiki_root=settings.wiki_root_path, payload=p)
    print('rebuilt', len(p['nodes']), 'nodes')
asyncio.run(m())
"''')
```

### 7.6 Neo4j 起不来 / 内存爆

`docker-compose.yml` 里 neo4j 限了 heap 768M + pagecache 256M。如果还崩，改更小：

```yaml
NEO4J_server_memory_heap_max__size: "512m"
NEO4J_server_memory_pagecache_size: "128m"
```

`docker compose up -d --force-recreate neo4j`。

### 7.7 docker compose 命令找不到

云服务器没装 v1，v2 plugin 在 `/usr/libexec/docker/cli-plugins/docker-compose`。重装：

```bash
mkdir -p /usr/libexec/docker/cli-plugins
curl -fL --max-time 180 -o /usr/libexec/docker/cli-plugins/docker-compose \
  'https://gh-proxy.com/https://github.com/docker/compose/releases/download/v2.29.7/docker-compose-linux-x86_64'
chmod +x /usr/libexec/docker/cli-plugins/docker-compose
docker compose version
```

> 直连 github 在云服务器上慢（13KB/s），用 `gh-proxy.com` 代理快（1.7MB/s）。

## 8. 一些坑（避雷）

1. **本地 Docker Desktop 走代理 7897**，代理挂了 docker pull/build 会全部失败。daemon.json 在 `C:\Users\lenovo\.docker\daemon.json`，改了重启 Docker Desktop。
2. **Windows 终端 GBK** 默认对中文 print 友好不了，paramiko 脚本加 `sys.stdout.reconfigure(encoding='utf-8')`。
3. **mysqldump 警告进 .sql 文件** —— 旧坑：`docker exec mysql mysqldump ... 2>/dev/null > dump.sql` 在 msys bash 下 `2>/dev/null` 不一定生效。用 `docker exec mysql sh -c "mysqldump ... 2>/dev/null"` 包一层。
4. **MySQL TEXT 列不能有 server_default**（migration 0008 踩过），用 nullable 或不设默认。
5. **uvicorn --reload** 在 docker 里我们没用（Dockerfile 里是普通 uvicorn）。本地 dev 才用 reload。
6. **alembic 自动升级**已经在 lifespan 里跑了，所以容器一启动 schema 就到 head，不用手动跑。
7. **APP_ENV=prod 下 dev 旁路鉴权关闭** —— `CurrentUserId` 没 token 就 401。诊断时绕开走 `docker exec ... python -c` 在容器里跑代码。
8. **公告图片 / 用户上传**会写到 `data/uploads/`，nginx 的 `/static/` 反代会把 `/static/uploads/announcements/xxx.png` 转给 backend `/static/uploads/...` 静态挂载。改 nginx 别忘了这个 location。

## 10. 给 Claude 的话

下次用户把这份文档丢过来 + 给一个新需求时：

- 优先用「**第 3 节增量改代码**」的方式（docker cp 单文件 + restart），不要重 build 镜像
- 改任何 .py/.vue 后**本地先跑一遍 dev 验证**（`uvicorn` + `npm run dev`）再推云端
- 上云端前**先复述要做什么**让用户确认（这是高风险操作）
- 用第 7 节的诊断模板调试，不要去猜
- 改完做 4 件事兜底：**docker compose ps + curl /health + 看 backend logs + 浏览器访问**
- 任何**清空 MySQL** / **覆盖 wiki/** / **改证书** / **改防火墙** 的动作必须显式让用户拍板
