# Step2a:摘要页 + 已有实体追加段

你已完成 Step1 结构化分析。本阶段只生成两类页面:

1. **本次素材的 source 摘要页** `wiki/sources/{date}-{slug}.md`
2. **已有实体页的追加观察段**(对每个 matched_entity_pages 项):仅输出 `## 不同素材中的观点 / ### 来源:[[{source_slug}]]` 段的新增内容

**新建实体页 / 新建主题页交给后续 Step2b / Step2c 单独深度生成,这里不要产出**。

### Step1 产出(JSON)

```json
{step1_json}
```

### 原始素材

```
{raw_md}
```

### 现有相关 wiki 页(用于合并参考;可能为空)

{related_pages_block}

## 输出格式

为下列每一类页面生成完整 markdown(含 frontmatter)。多份页面之间用以下分隔符:

```
=====<file: wiki/sources/{slug}.md>=====
(该页面 markdown 全文,含 frontmatter)
=====<file: wiki/entities/{slug}.md>=====
(只输出"## 不同素材中的观点 / ### 来源:[[{source_slug}]]" 段的内容,frontmatter 仅含 slug 字段,后端会做合并)
```

- `=====<file: ...>=====` **必须在同一行**(不许在 `=====` 与 `<file:` 之间换行,也不许在 `>` 与 `=====` 之间换行)
- 分隔符前后必须各空一行
- 每份页面以 frontmatter `---\n...\n---` 开头
- 不要在分隔符之外添加任何解释文字

## source 摘要页要求(深度模式)

参考 `templates/source.md` 模板,**严格按以下 9 段输出,每段都要写满,不要省略**:
1. `## 来源元数据`(列表)
2. `## 一句话定位`(≤120 字)
3. `## 整体摘要`(200-500 字)
4. `## 核心要点`(≥5 条,每条 ≥40 字,带具体数字/案例/人名)
5. `## 抽取的实体`(每条 [[实体名]]:在本素材中的位置/作用,≥30 字)
6. `## 抽取的主题`(每条 [[主题名]]:在本素材中如何展开,≥30 字)
7. `## 关键论据与数据`(≥3 条,带原文片段)
8. `## 与现有知识库的关系`(100-300 字;现有 wiki 为空时写"(首次入库,无对比)")
9. `## 原文(节选)`(2-4 段直接引用,保留原文措辞)

source 摘要页 frontmatter 必填字段:
```yaml
---
title: <素材标题>
slug: <date>-<slug>
kind: source
source_type: <source_type 来自 documents 表>
domains: <来自 step1.source_summary.domain_tags>
key_takeaways: <来自 step1.source_summary.key_takeaways>
sources: []
version: 1
---
```

## 已有实体页追加段要求

对每个 `matched_entity_pages` 项,只输出 `## 不同素材中的观点 / ### 来源:[[{source_slug}]]` 段下的具体内容,**不要重写整页**:

```
---
slug: <已有实体 slug>
---

## 不同素材中的观点

### 来源:[[{source_slug}]]

{本素材中关于该实体的新主张/补充观点/不同视角,150-400 字,引用原文证据}
```

主张冲突时(对应 Step1 contradictions),用 `> ⚠ 与来源 [[{other_slug}]] 的主张可能冲突` blockquote 标注。

## 引用规范

- 提到其他实体写 `[[实体名]]`(双链)
- **引用格式铁律**:每条 `> 引自来源:[[{source_slug}]]:...` **必须独占一行、行首顶格写 `>`**,绝不能接在正文句尾(如 `…结束。 > 引自来源` 是错的);引用块与上方正文之间、多条引用之间都**必须空一行**;source 名**必须用 `[[ ]]` 双链**,不能写裸 slug。
- 关系类型注释(可选):注释必须写在 `]]` **之后**,绝不能写进 `[[...]]` 内部。
  - 正确:`[[X]] <!-- type: 实现 --> <!-- confidence: EXTRACTED -->`,后端会同步到 wiki_links 表
  - 错误:`[[X<!-- type: 实现 -->]]`(注释写进双链内部会导致链接失效)
  - 双链 `[[X]]` 里只能是页面名本身,不能含任何 `<!-- -->` 注释、空格说明或标点。
