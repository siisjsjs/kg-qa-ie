# 实体页跨素材融合(写成一份,而非并列两份)

同一个实体 `{entity_title}` 在多个素材里都出现了。下面给你这个实体的**两份输入页全文(输入页 A、输入页 B)**。

你的任务:把两者**融合成一份统一的实体页**——只有**一个定义、一套章节**,内容综合两份素材。**绝对不要**保留两份并列的定义,也不要用"## 不同素材中的观点 / ### 来源:[[X]]"这种把其中一份单独堆在下面的写法。

## 融合原则

1. **一个定义**:`## 定义` 段只写一段权威定义,综合两份素材的表述。若两份对同一概念有互补的角度,糅合成一段连贯的定义,而不是先写 A 的定义再写 B 的定义。
2. **逐段合并**:其余每个 H2 段(核心特征 / 历史与发展 / 适用场景 / 指标量化 / 典型案例 / 常见误区 / 与相关概念区别)都把两份素材的对应内容**合并去重**:相同的点合并,互补的点累加,更详尽的表述优先保留。
3. **不丢信息**:任一份素材独有的案例、数字、人名、年份、公式都要保留。原文证据引用 `> 引自来源:[[slug]]:...` 保留并标清来自哪个 source。
   - **引用格式铁律(融合时极易踩坑,务必遵守)**:每条 `> 引自来源:[[slug]]:...` **必须独占一行、行首顶格写 `>`**,与上方正文之间空一行,多条引用之间也各自空一行。**绝对禁止**把多条引用挤在正文段落尾部、用 ` > ` 串在同一行(如 `…融为一体。 > 引自来源:A… > 引自来源:B…` 是错的,前端会把它整段当正文渲染)。source 名必须 `[[ ]]` 双链,不能裸写。
4. **冲突显式标注**:若两份素材对同一事实有**矛盾**主张,在该处用 `> ⚠ 来源 [[来源1-slug]] 与 [[来源2-slug]] 的说法不一致:...` 一句话点明(用具名 slug,不要用 A/B),不要静默二选一。
5. **sources 合并**:frontmatter 的 `sources` 取两份的并集。`## 参考来源` 段列出所有来源 `- [[slug]]`。
6. **保持 9 段骨架**:沿用 定义 / 核心特征 / 历史与发展 / 适用场景与方法 / 指标与量化 / 典型案例 / 常见误区与边界 / 与相关概念的区别 / 参考来源 的结构。删掉任何"## 不同素材中的观点"段。
7. **version**:取两份 version 的较大值。
8. **严禁相对称呼来源(铁律)**:正文里**绝对不能**出现"已有素材 / 新素材 / 本次素材 / 上一份素材 / 前一份 / 另一份素材 / 第一份 / 第二份"这类**以入库顺序或批次指代来源**的措辞——读者不知道这是哪份,而且这是"两份贴在一起没真融"的信号。
   - 默认写法:**直接陈述事实**,把两份内容糅成一段连贯叙述,不提"来自哪批"。例:✅「工业工程的适用场景可归纳为……既包括离散型制造,也包括流程型制造与服务型企业。」 ❌「根据已有素材,场景有三层;根据新素材,场景包括……」
   - 确需点明出处时(如引用原文、标注冲突),**只能用具名 `[[source-slug]]`**,例 `> 引自来源:[[2026-06-06-第二章-工业工程概述]]:...`,绝不用"已有/新"等相对词。
   - 自检:输出前通读全文,凡出现"已有/新/本次/前一/另一份 + 素材"一律改写。

## 双链白名单铁律

正文所有 `[[X]]` 里的 X **必须逐字来自下方"可引用实体白名单"**。白名单里没有的概念只写纯文本,绝不加 `[[ ]]`。关系注释只能写在 `]]` 之后,绝不能写进 `[[...]]` 内部。

**关系类型注释保留(铁律)**:两份输入页里凡是写成 `[[X]] <!-- type: 实现 --> <!-- confidence: ... -->` 形态的双链,融合后**必须原样保留 `<!-- type: ... -->` 和 `<!-- confidence: ... -->` 注释**——这是实体间语义关系(实现/依赖/对比/矛盾/衍生)的唯一载体,丢了关系图谱的边就退回成「相关」。
- 同一个 `[[X]]` 在两份里类型不同时,保留更具体的那个(非「相关」优先);都具体且冲突时,保留 confidence 更高的(EXTRACTED > INFERRED > AMBIGUOUS)。
- 融合去重让某个 `[[X]]` 只剩一处时,把原有的 `<!-- type -->` 注释一并带到保留的那处。
